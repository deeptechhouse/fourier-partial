fourier_partial

Drop in a few seconds of audio. Get back the individual tones it is actually made of — each one visible, each one soloable, each one exportable as audio or as notes. Play them all together and you get your recording back, sample for sample.

Quick start

1. Set up the environment (once)

cd /Users/aaandy/_andy_ai_projects_2026/fourier_partial
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

2. Run it

Double-click FourierPartial.app in Finder. It starts the server, waits until it answers, and opens your browser.

Or from a terminal, which is better when something goes wrong because you can see the errors:

./run.sh              # starts the server and opens a browser
./run.sh --no-open    # server only

3. Use it

  1. Drop in a WAV, FLAC, AIFF or OGG file — up to 30 seconds.
  2. Wait a moment while it analyses.
  3. You get a stack of tracks. Each row has M (mute) and S (solo), a note name, and a picture of that tone's pitch over time.
  4. Press Play. Solo one track to hear a single pure tone with the original's vibrato and decay intact.
  5. Unmute everything — that is your original file, exactly.
  6. wav / mid on any row exports it.

If the app does nothing when double-clicked

It should always show a dialog rather than fail silently. If it does not, run ./run.sh in a terminal — the error will be on screen. The server log is at logs/server.log.

What it actually does

A Fourier transform tells you which frequencies a sound contains. Doing that in short overlapping windows tells you which frequencies are present when. Link those across time and each becomes a partial: one tone's entire life, sliding and swelling and fading.

Group the partials that belong to one note, render each group back to audio, and you have tracks. Then comes the one decision everything else rests on — the leftovers are defined as a plain subtraction:

residual  :=  original  −  Σ partials

which means, rearranged:

Σ all tracks  ≡  original

Not approximately. Identically — and regardless of how well the analysis performed. Every partial could be mistracked and the mix would still reproduce your upload sample for sample. That is asserted on every analysis and measured at 2.98e-08 (float32 rounding) end to end over HTTP.

What lands where

MaterialWhere it goesWhy
Sustained tonesPitched tracksSparse in frequency, so few partials describe them
HarmonicsGrouped with their fundamentalYou want to solo the note, not its 3rd harmonic
Clicks, breath, noiseThe residualCannot be sparse in frequency — see below

The residual is not an error bucket

A signal cannot be concentrated in both time and frequency at once. A click is maximally concentrated in time, so its energy must spread across all frequencies, and no finite set of tones can represent it. The residual is where the mathematics says that material has to go — so it is a first-class track with its own character (the pick, the bow, the breath), not a failure.

About MIDI export

A partial is a continuous curve; MIDI is discrete events on a 12-tone grid, so converting loses information. Pitch becomes a note plus a pitch bend (range widened to ±48 semitones via RPN 0, without which glides silently clip), and amplitude becomes velocity plus CC 11.

Export is one file per track because pitch bend applies to a whole MIDI channel — tracks sharing one would bend each other. The residual has no MIDI export at all: it is broadband noise, and writing it as notes would be inventing information rather than converting it.

Architecture

frontend/          canvas trajectories + sample-accurate Web Audio playback
   |  HTTP + WebSocket
backend/api/       routes, background jobs, progress socket
backend/analysis/  stft -> peaks -> tracking -> grouping
backend/synthesis/ oscillator bank; owns the reconstruction invariant
backend/export/    wav (lossless) + mid (lossy)
backend/core/      types, ports, errors — depends on nothing

Ports and adapters throughout: every replaceable concern sits behind a Protocol in backend/core/interfaces.py, so swapping the tracker, the renderer or the audio backend means writing one class and changing one line in backend/services.py.

Development

Every tunable lives in AnalysisParams (backend/core/types.py) and every adjustable constant elsewhere is marked with the word ADJUSTABLE and an explanation of which way to turn it.

Known gap

pyproject.toml still excludes the now-implemented modules from the 90% coverage gate — a scaffolding measure that has outlived its purpose. Those omit lines should be removed one at a time, adding tests until each module passes on its own. The gate cannot tighten while they are listed.
